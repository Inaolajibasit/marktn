# Repository instructions

## Project context maintenance

- Read CONTEXT.md before working on this repository, alongside other applicable instructions and current source.
- After every codebase change, update CONTEXT.md as part of the same task before handing work back to the user. This includes changes to source, configuration, dependencies, assets, and project documentation.
- Keep relevant architecture, routes, content ownership, integration details, environment variable names, and known issues accurate. Remove or mark resolved findings when fixed.
- Add a concise dated change-log entry describing affected files, the purpose of the change, and verification results or limitations. Never claim a check passed unless it was run successfully.
- Never put credentials, tokens, or secret environment values in context files.
- For read-only tasks, update context only if new findings correct or materially extend the recorded project knowledge.
